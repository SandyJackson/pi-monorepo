# Git worktree patterns in the Pi coding agent ecosystem

**Scope.** Public, primary-source survey of Git worktree implementations and extensions built for Pi (`earendil-works/pi`, formerly `badlogic/pi-mono`). It covers: extensions that create/select/switch worktrees, launch or replace Pi instances, hand off or clone sessions across working directories, use terminal multiplexers (tmux/zellij/WezTerm/cmux/Herdr), or override cwd-bound tools. Sources are repository code and READMEs, Pi's shipped docs and examples (read from the installed package, v0.85.1 tree), and Pi issues/PRs. Every claim links to the file or issue it comes from. Links to GitHub `main` were captured via the GitHub API at research time; files are at `main` unless otherwise noted.

**Method.** GitHub code search for `pi-coding-agent` + `worktree`, plus issue/PR search against `earendil-works/pi`, plus local inspection of cloned mirrors of `mitsuhiko/agent-stuff`, `juicesharp/rpiv-mono`, `fullerzz/herdr-plugin-sesh`, and the Pi monorepo itself. All extensions below are independent public repos; none are affiliated with the Pi maintainers except where noted.

---

## Summary

Pi binds its tools, session storage, trust state, and extension contexts to the cwd captured at session start. There is **no supported API to change a live session's cwd** — the maintainer said so explicitly (issue #2992), and every proposed API (`setCwd`, `switchCwd`, `relocateSession`, `pi --worktree`) has been auto-closed without being adopted. The ecosystem has converged on three working patterns instead:

1. **Session replacement across cwds** — fork or create a session file whose header records the worktree path, then call `ctx.switchSession()`, which tears down and rebuilds the cwd-bound runtime. This is the dominant verified pattern (≈15 implementations).
2. **Effective-cwd tool routing** — intercept `tool_call`/`user_bash` and rewrite paths and commands into the active worktree without moving the session. Safer for cleanup, weaker in fidelity (session header, pickers, and autocomplete stay at the old cwd).
3. **New Pi process in the worktree** — spawn or relaunch Pi in a separate pane/tab (tmux, zellij, WezTerm, cmux, Herdr) either as a child worker or as a process swap that hands the conversation over via `--session <forked-file>`.

For subagent workloads, a fourth family exists: **worktree-isolation providers** that create a detached worktree per child run and hand back a patch/branch, with no session relocation at all.

Everything below separates **verified implementations** (code inspected) from **proposals and declined upstream work** (issues/PRs).

## 1. What Pi core supports today (verified against docs and source)

This is the API surface every implementation builds on. Sources: `docs/extensions.md`, `docs/session-format.md`, `docs/sdk.md` in the installed package, and `packages/coding-agent/src/core/` in `earendil-works/pi`.

- **`ctx.switchSession(sessionPath, { withSession })`** — "Switch to a different session file". After replacement, `ctx.cwd`, `SessionManager`, and the rebuilt tool stack re-root to the target session's header cwd; only `process.cwd()` stays behind. Extensions may cancel via `session_before_switch`. Documented with the footgun that captured old contexts are stale inside `withSession`: `docs/extensions.md`, "Session replacement lifecycle and footguns" (https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/extensions.md). Type declarations: `packages/coding-agent/src/core/extensions/types.ts` (lines ~380, ~1672).
- **`ctx.newSession({ parentSession, setup, withSession })`** and **`ctx.fork(entryId, { position, withSession })`** — same replacement lifecycle, but always within the current cwd's session directory (there is no `cwd` option; that gap is issue #8269, see §4).
- **`SessionManager.forkFrom(sourcePath, targetCwd, sessionDir?, options?)`** — copies a session's full entry set into a new file whose header records `targetCwd` and `parentSession: sourcePath`. Verified in `packages/coding-agent/src/core/session-manager.ts` (`static forkFrom`, ~line 1579). Requires a non-empty source file and a header; empty/ephemeral sessions cannot be forked.
- **`SessionManager.create(cwd, sessionDir?)`** — creates a new session bound to `cwd`. Lazy-persistence footgun: nothing is written until the first assistant message, so `switchSession` on a bare header silently falls back to `process.cwd()`. Implementations work around this by writing the header eagerly with flag `"wx"` (alennartz `my-pi`, HamdiMaz/Worktree via a synthetic sentinel assistant message, arkrost `wt.ts`, BrandonMathis `my-pi`, MichaelT025/Dispatch).
- **`agent_settled` event** and **`ctx.isIdle()` / `ctx.waitForIdle()`** — the synchronization points for deferred switches. `agent_settled` was added on main after the spike in issue #2023 ("Add pi.runWhenIdle() to schedule work after the agent has fully settled", closed 2026-07-09). A successor proposal for *atomic* idle submission (issue #9632, "Extensions need atomic idle submission for timer-driven work") was closed without adoption; no `pi.runWhenIdle()` exists in shipped types.
- **Tool override factories** — `createBashTool(cwd, { spawnHook })`, `createReadTool(cwd, ...)`, etc., plus the `user_bash` hook that can replace local bash operations, and `tool_call` interception that can rewrite `event.input` in place. Documented: `docs/extensions.md` ("Adjust bash command, cwd, and env before execution", example index `bash-spawn-hook.ts`, `tool-override.ts`).
- **Session identity** — sessions are stored per encoded cwd (`~/.pi/agent/sessions/<encoded-cwd>/`); `SessionManager.list(ctx.cwd)` filters by cwd. Issue #8271 ("repo-scoped sessions", closed) documents the consequence: each worktree's sessions are a disconnected "project"; the proposal to group by git common-dir was closed without implementation. Related friction documented (not merged): PR #9754 / issue #9753 — resuming a worktree-born session from a sibling checkout via a symlinked session dir triggers the "Fork this session into current directory?" prompt because session-dir comparison is lexical; PR closed unmerged.
- **Worktree-aware behavior that *is* shipped** — the footer resolves the branch through the `.git` file indirection of linked worktrees (PR #490, `packages/coding-agent/src/core/footer-data-provider.ts`); nested linked worktrees no longer double-load context files (`resource-loader.ts` `findShadowedContextFile`, PR #7221 fixing #6617); a session whose recorded cwd no longer exists raises `MissingSessionCwdError` with a fallback prompt (`packages/coding-agent/src/core/session-cwd.ts`).
- **Pi ships no worktree extension example.** The installed example set (`examples/extensions/`) contains none, and grep over shipped docs/examples finds no `worktree` mention. A packaged `worktree-agent` example was proposed (issue #5276, PR #5246 by `yug-space`) and closed unmerged — see §4.

## 2. Verified implementations — session replacement into a worktree

The common shape: `await ctx.waitForIdle()` → `SessionManager.forkFrom(sessionFile, worktreePath)` (or `.create`) → optionally strip the fork header's `parentSession` → `await ctx.switchSession(newFile, { withSession })` → clean up the old file. Commands only: `switchSession` is on `ExtensionCommandContext`, not on tool-handler contexts.

### 2.1 `narumiruna/pi-extensions` — `packages/pi-worktree` (`@narumitw/pi-worktree`)
https://github.com/narumiruna/pi-extensions/tree/main/packages/pi-worktree

- One guarded `/worktree` manager: list (main/linked/current/detached/locked/prunable, with status cards), create from new or unoccupied branch, switch, remove, prune. Default root `~/.worktrees/<repo>/<slug>`; configurable via `~/.pi/agent/pi-worktree.json` (`worktreeRoot`), reloaded on every `session_start`.
- Switch semantics, quoted from README: switching "forks into the target worktree" the linear persisted session, then Pi "tears down the old cwd-bound runtime and creates the target runtime"; success is reported only through the fresh replacement-session context. Empty sessions get a fresh valid session; `--no-session` ephemeral conversations are copied into a persisted target so context survives.
- Failure behavior: if switching fails after Add, the Git worktree and any prepared target session are retained for retry via **Switch worktree**.
- Limits (README "Limitations"): needs TUI/RPC (print/JSON rejected), non-bare worktree, and "project trust and cwd-bound extension/resource loading during a switch remain owned by Pi". MVP does not expose `--force`, `-B`, `--detach`, `--orphan`, lock, move, or repair.
- Notable hardening: removal refuses main/current/locked/stale worktrees, dirty trees, submodules, and intentional `skip-worktree`/`assume-unchanged` index state; recovery-pointer loss is enumerated before destructive confirmation; only argv-form `git worktree remove <path>` is ever run — never a shell, `rm`, or Node fs deletion.

A maintained fork adds Jujutsu workspace support (`elrond298/pi-worktree`, https://github.com/elrond298/pi-worktree): same `/worktree` surface, but manages `jj workspace add/forget/list` in colocated or `.jj` repos, including pruning stale workspaces only when clean.

### 2.2 `ogulcancelik/pi-extensions` — `packages/pi-worktree` (`@ogulcancelik/pi-worktree`)
https://github.com/ogulcancelik/pi-extensions/tree/main/packages/pi-worktree

- `switch_worktree` tool + `/switch-worktree <path>` command. The tool **pre-fills the editor** with the command rather than switching directly ("Press Enter to confirm"), setting `pendingWorktreeSwitch` state cleared by the `input` event. Quirky but deliberate: keeps the human in the loop at exactly the relocation point.
- Switch mechanics (verified in `packages/pi-worktree/index.ts`): validate non-bare git tree → confirm → `SessionManager.forkFrom(currentFile, target)` → delete `parentSession` from the fork header → `ctx.switchSession(newFile, { withSession })` → unlink the old session file → `sendUserMessage("Session relocated to worktree: ... Continue working.")` to auto-continue. Cancellation rolls back by unlinking the fork.
- Herdr integration: while a switch is pending it emits `herdr:blocked` events (`HERDR_ENV`) so the Herdr UI shows a pending state.
- Limit: requires a persisted session; ephemeral sessions cannot switch.

### 2.3 `ogulcancelik/pi-extensions` — `packages/pi-herdr-worktree-jump`
https://github.com/ogulcancelik/pi-extensions/tree/main/packages/pi-herdr-worktree-jump

- Herdr-only (`HERDR_ENV === "1"`). `herdr_worktree_jump` tool: resolves the source checkout via `herdr worktree list --cwd <pi-cwd>`, then either `herdr worktree create` (branch/base/label parameters; Herdr generates a branch name if omitted) or `herdr worktree open` for `destination: "main"`.
- Then, in order: fork the persisted session into the destination checkout (`SessionManager.forkFrom`, strip `parentSession`), start the replacement in the destination pane with `herdr pane run <pane> 'pi --session <file> Moved to worktree <path>. Continue.'` (source: `runInNewPane`, `packages/pi-herdr-worktree-jump/index.ts`), and schedule detached cleanup (`setsid`/`nohup` shell script) that waits up to 60 s for the old PID to exit, `rm -f`s the old session file, and closes the old pane.
- Explicit invocation policy in prompt guidelines: only when the *user explicitly asks to jump*; never inferred from "isolation would be useful". Requires Pi ≥0.80, Herdr ≥0.8.0, persisted session, `HERDR_PANE_ID`.

### 2.4 `MichaelT025/Dispatch` — `extensions/pi-worktree/git-worktree.ts`
https://github.com/MichaelT025/Dispatch/tree/main/extensions/pi-worktree

- `/worktree` (`/wt`): ls / add / open / rm / pr (via `gh`, verifying PR head) / **resume** (a picker of sessions from *any* checkout of the repo, grouped across worktrees).
- `add`, `open`, an `ls` selection, and `pr` switch the interactive CLI into a **fresh empty session** in the target worktree: `SessionManager.create(targetPath)` with an eagerly persisted header, then `ctx.switchSession(created.file, { withSession })`. "The current conversation is never copied or modified" — the header comment states the design: `ctx.switchSession` rebuilds tools, extensions, resources, trust, and Dispatch worker cwd; other (non-TUI) hosts keep path-copy behavior only.
- Refusal and recovery engineering: switching refuses while the agent, a compaction/branch summary, queued messages, or PiAstra workers are busy; if the switch is refused/cancelled/failed the created worktree is kept and its path reported; the old session file is never modified, and the recovery hint `pi --session "<sourceFile>"` is shown *before* teardown because the old context may already be invalid afterwards. Cancelled switches delete their own just-created empty session file (verified content check in `removeOwnUnusedSession`).

### 2.5 `BrandonMathis/my-pi` — `agent/extensions/worktree.ts`
https://github.com/BrandonMathis/my-pi/blob/main/agent/extensions/worktree.ts

- `/worktree [branch]` with action picker; worktrees at `<repo-root>/.pi/worktrees/<branch>`, excluded via the repo's `.git/info/exclude` (`EXCLUDE_PATTERN = ".pi/worktrees/"`).
- On create/switch it asks **Keep conversation context (fork session)** vs **Start fresh**, then either `SessionManager.forkFrom(currentSessionFile, targetDir, projectSessionDir)` (fork is deliberately placed in the *project* session dir so it groups with the main repo's sessions) or `SessionManager.create` + eager header write, then `ctx.switchSession`.
- Remove flow moves the session back to the main repo first (keep-or-clear context) when you are inside the worktree being removed, then removes; dirty trees need a second force confirmation.
- Comment in source: git runs via `spawnSync` because it must be "context-independent... safe to call from `withSession` callbacks after a session switch, where the captured extension API may be stale".

### 2.6 `HamdiMaz/Worktree`
https://github.com/HamdiMaz/Worktree

- `/worktree <name>`: create-or-reuse a worktree, copy project `.pi` resources into it, then `switchToFreshWorktreeSession` (`extensions/session.ts`): fork from the persisted seed session if it exists, otherwise `SessionManager.create` + a **synthetic "persistence sentinel" assistant message** (`stopReason: "aborted"`, zero usage) to force Pi to write the file, `resetLeaf()`, append a custom `pi-worktree` entry ("You are in git worktree `...` on branch `...`. Please keep all changes in this worktree."), then `ctx.switchSession`. The sentinel trick is the cleanest published fix for the lazy-persistence footgun.

### 2.7 `FradSer/pi-packages` — `packages/utils/extensions/worktree-session.ts`
https://github.com/FradSer/pi-packages/tree/main/packages/utils/extensions

- Header comment states the core mechanic plainly: "Pi binds its built-in tools to the session cwd, so entering a worktree creates a replacement session with that cwd instead of mutating process.cwd."
- Enter/exit pair: enter forks the source session into the worktree path, appends a custom `pi-utils-worktree-session` entry recording branch, base commit, repo root, and **the parent session path**; exit (`switchOutOfWorktree`) reads that entry and `ctx.switchSession(state.parentSession)`, offering to remove the worktree (dirty-aware choices) on the way out. Cancel-on-enter removes the just-created worktree and fork file.
- Sibling extension `worktree-completion.ts` wraps the editor autocomplete provider so `@` suggestions from *other* worktrees (main checkout seen from a worktree, or sibling worktrees) are dropped.
- Sibling extension `worktree.ts` is a different pattern: a `tool_call` hook that tokenizes a small safe shell subset and rewrites plain `git worktree add <path>` targets into `.pi/worktrees/<name>`, leaving anything with shell operators, substitutions, or globs unchanged.

### 2.8 `alennartz/my-pi` — `extensions/worktree/`
https://github.com/alennartz/my-pi/tree/main/extensions/worktree

- Full controller with interactive choices: **bring context vs fresh session** and **bring pending changes (stash push/pop) vs leave changes**; worktrees under `.git-worktrees/`; merge-back resolves a target from `origin/HEAD` → `init.defaultBranch` → local heuristics → `main` fallback.
- Two published insights worth copying:
  - Eager header write with `"wx"` because "pi persists sessions lazily — nothing is written to disk until the first assistant message. But `switchSession` resolves the session's cwd from the file header, and a missing file silently falls back to `process.cwd()`" (source comment, `extensions/worktree/index.ts`).
  - Forked history "is saturated with absolute paths from the old checkout"; it appends a visible custom entry `worktree:moved`: "Your working directory is now ... omit `cd` and use relative paths. Absolute paths mentioned earlier ... refer to a different checkout — do not use them and do not `cd` to them." This addresses a real failure mode none of the simpler forks handle.

## 3. Verified implementations — other patterns

### 3.1 New Pi process in the worktree (child or replacement process)

- **`RielJ/pi-git-worktrees`** — the most complete multiplexer orchestration. All child Pi agents live as windows in one hidden tmux session `_pi-wt`; viewing uses `tmux display-popup`; messaging uses `tmux send-keys`; a hidden-session pool is created with `destroy-unattached off` (source: `src/tmux-swap.ts`). Child session is created with `SessionManager.create(worktreePath, sessionsDir)` plus a custom `pi-git-worktrees/session` metadata entry, and spawned as `pi -e <self> --session <file>` in the worktree; when not inside tmux it falls back to headless `pi -p` background runs (`src/index.ts`). Tools: `wt_new / wt_send / wt_wait / wt_gather / wt_context`; slash commands `/wt-new`, `/wt-switch`, `/wt-send`, `/wt-context`, `/wt-merge`, `/wt-diff`, `/wt-remove`; a status widget shows per-worktree activity; heartbeat detects busy/idle. Requires tmux 3.2+. README documents `allow-passthrough`, `history-limit 10000`, and a `bind-key W` popup attach. https://github.com/RielJ/pi-git-worktrees
- **`simonamtoft/pi-worktree-agents`** — WezTerm-native: `wezterm cli spawn|split-pane --cwd <worktree> -- env PORT=<n> PI_WORKTREE_NAME=<name> pi --name wt:<name> [prompt]` (source: `launchWezterm`, `extensions/worktree-agents.ts`). Per-worktree dev-port allocation stored in git config `branch.<branch>.pi-worktree-port`; a `worktree_browser` Playwright tool is scoped to the assigned port; Backlog.md task context and a `worktree` git-config excludes file; post-create hooks with per-step status. Managed list/merge/remove under `/wt-list`, `/wt-merge`, `/wt-remove`. https://github.com/simonamtoft/pi-worktree-agents
- **`julianbenegas/my-pi`** — `extensions/by-the-worktree.ts`: `/btworktree <base>/<name> <prompt>` creates a worktree + persisted session (`SessionManager.create`), then runs the child **headless** (`pi -p --session <file>` with inherited model/thinking/tools, env-inherited) on the task prompt, then loops a decision prompt until the child reaches a verified terminal state — either "KEEP" (committed and pushed, verified by `git status --porcelain` empty and `git rev-list --count @{u}..HEAD` = 0) or "DISCARD" (`reset --hard <target>` + `clean -fd`, same verification) — then removes the worktree. Deterministic finalization loops with forced discard after several attempts. https://github.com/julianbenegas/my-pi
- **`gabrielmbmb/pi`** — `extensions/worktree.ts`: the exec-swap variant of launch. It registers Pi flags `--worktree <branch>`, `--worktree-base`, `--worktree-session` and, at extension *factory time* (before Pi paints its first frame), if invoked with `--worktree` on a TTY, creates/reuses the worktree and re-execs `pi` with the same args plus `--session` in the worktree cwd, keeping the bootstrap alive until the child exits. A `session_shutdown { reason: "quit" }` hook prints `To resume this worktree session: pi --worktree <branch> --worktree-session <file>`. It also clears the terminal (`\x1b[2J\x1b[H\x1b[3J`) before the child inherits the TTY because "Pi's first render assumes a clean screen". An LLM tool `worktree_switch` does not switch immediately — it queues the switch and returns `terminate: true`, and an `agent_settled` handler re-dispatches `/worktree <branch> --continue` through `pi.sendUserMessage` so the tool result is persisted first (with guards for RPC/print callers). This is the best-documented in-repo solution to the "can't switch from inside a running turn" problem. https://github.com/gabrielmbmb/pi
- **`w-winter/dot314`** — two extensions:
  - `pi-move-session` (`extensions/move-session.ts`): self-replacement — fork session into the target cwd bucket, clear `parentSession`, tear down the parent's terminal state (Kitty protocol, bracketed paste), spawn `pi --session <fork>` with inherited stdio, then trash the old session (via the `trash` binary; "If 'trash' isn't available, do not fall back to unlink") and destroy the parent's stdin so it cannot steal keypresses. The parent remains as an inert wrapper forwarding the child's exit code. Supports `$main-worktree` to return to the main checkout, and warns when the current `/tree` selection is not the default branch tip because the selection is not preserved. https://github.com/w-winter/dot314
  - `pi-branch-out`: `/branch` forks the session (same cwd — not a worktree pattern, but the same session-fork plumbing) into a split pane or tab across a backend matrix (Orca, cmux, tmux, iTerm2, Terminal.app, Ghostty, Alacritty), with stateful rotating split policies persisted in `/tmp/pi-branch-out-layout-state.json`. Useful reference for backend capability tables (which backends support tab vs static vs rotating splits). https://github.com/w-winter/dot314
- **`dingdinglz/pi-worktree`** (`@dinglz/pi-worktree`, npm) — a full task-lifecycle manager: `/wt new <task>` creates a worktree from committed HEAD under `~/.pi/worktrees/<host>/<repo>/<slug>`, records the exact source checkout/branch/SHA, runs approved `postCreate` hooks (optionally proposed by an isolated, tool-less Pi process that sees only an allowlist of manifests), then "opens a fresh pi session in a detected terminal tab (or prints an exact manual command)" — launcher auto-detects tmux, Apple Terminal, iTerm2, WezTerm, Kitty, Ghostty, GNOME Terminal, Konsole, with an argv-template custom launcher. `/wt finish pr|merge` runs quality gates, pins pushes to the reviewed commit SHA, verifies the remote SHA and PR head/base, executes `git merge --ff-only` in the *recorded* source checkout (never an assumed main dir), and removes the worktree after confirmation. Config layering: defaults → `~/.pi/agent/worktree.json` → user-local per-repo → trusted project `.pi/worktree.json`; hooks receive `PI_WT_PATH`, `PI_WT_SOURCE_PATH`, `PI_WT_BRANCH`, etc. Strict: no `--yes` bypass, structured argv execution by default. https://github.com/dingdinglz/pi-worktree
- **`jbpratt/pi-experiments`** — `extensions/lazyworktree`: treats an external CLI (`lazyworktree`) as the worktree manager. Main-checkout protection (fail-closed confirmation per mutating tool call), a `workspace` tool (`status/list/prepare/create/rebase/merge`), and tmux `new-window` launch of Pi in the created workspace when inside tmux; hard-blocks direct `git worktree add|move|remove|prune|repair|lock|unlock` so lifecycle changes cannot bypass LazyWorktree. https://github.com/jbpratt/pi-experiments/tree/main/extensions/lazyworktree
- **`pcone/pi-config`** — `extensions/worktree-guard.ts` + `extensions/subagent-async/index.ts`: parent creates a detached worktree per subagent at `<os.tmpdir()>/pi-subagent-wt-<suffix>` (branch `pi-subagent-<suffix>`), optionally overlaying the parent's uncommitted state ("carry"), then spawns the child with `--mode rpc` and env `PI_SUBAGENT_WORKTREE` / `PI_SUBAGENT_PARENT_CWD`; the `worktree-guard` extension wraps `read/write/edit/find/grep` in the child to block writes into *other* subagents' worktrees and the parent checkout, and deliberately does **not** wrap bash ("the responsibility of the official sandbox extension"). Notable production lessons in code comments: passing the `git()` result object instead of `.stdout.trim()` as a path "silently kills the carry overlay", caught by real-dispatch E2E, not mirror tests; carried-state snapshots let the completion filter detect files the child never touched. https://github.com/pcone/pi-config

### 3.2 Worktree-isolation subagent providers (no session relocation)

- **`yan-xie-nk/pi-extension-worktree-isolation`** — `isolated-subagent` tool. Parallel tasks each get a worktree under `.pi/worktrees/<slug>` with branch `pi-worktree-<slug>` from HEAD; `node_modules` is symlinked from the main repo (configurable via `symlinkDirs`); clean worktrees are auto-removed, dirty ones kept and reported with the branch name. Change detection **fails closed** (git status failure ⇒ keep). Child processes are spawned with `--mode json -p --no-session` plus optional `--append-system-prompt` from a 0600 temp file. `chain` mode "currently runs without worktree isolation" (README). Safety model in README: argv-only git, worktrees only inside `.pi/worktrees/`, cleanup only of worktrees it created. https://github.com/yan-xie-nk/pi-extension-worktree-isolation
- **`nicobailon/pi-subagents`** — the highest-signal implementation of managed isolation in the ecosystem (3.7k★). Worktree lifecycle in `src/runs/shared/worktree.ts`: provider selection `"auto" | "native" | "worktrunk"` (worktrunk used when the `wt` CLI capability check passes), branch naming with length caps (`pi-subagents/<...>`), fail-closed path validation before `git worktree add`, `node_modules` symlink with junction handling on Windows, setup-command execution with process-tree ownership (`worktree-setup-command.ts`), and a cleanup engine with three intents: `preserve` (with captured diff + handoff manifest), `discard` (policy- or confirm-authorized), `setup-rollback`. Workflow integration (`docs/workflows.md` "Worktree isolation"): `worktree: true` per child or per workflow; sources must be Git repos with clean trees before a materialized group dispatches; `baseRef` supports named refs only (not raw SHAs or `HEAD~1`); isolation "is never dropped automatically". The lane doctrine in `skills/pi-subagents/references/multi-lane-orchestration.md` ("one writer per repo/cwd or worktree", lane board with "isolation path" recorded before first mutation, "keep lane worktrees outside auto-discovered extension directories such as `~/.pi/agent/extensions`") is the most complete published operations guidance for worktree-based parallelism in the Pi ecosystem. https://github.com/nicobailon/pi-subagents
- **`nicknisi/pi-extensions`** — `packages/shared/worktree.ts`: "Pi-free git worktree primitives" — detached worktree per run at `~/.pi/agent/subagent-worktrees/<runId>` from HEAD, every git call `spawnSync` with 30 s timeout and *never throws* (failures surface as error strings; setup/teardown is best-effort). `packages/subagents` adds `worktree: true` per task; on completion the full delta *including untracked files* ("which a plain `git diff HEAD` silently misses") is captured as an untruncated patch at `~/.pi/agent/subagent-runs/subagents/<runId>.patch`, and a `/patches` staging overlay pre-flights with `git apply --check` and applies with `--3way`. Cleanup policy: 7-day inspection window with startup GC; aborted or ungracefully killed runs are reaped and their worktrees removed; documented honest cuts ("`stale` vs `conflicts` is decided by whether a modified target file still exists... not by a true base-commit comparison"). https://github.com/nicknisi/pi-extensions
- **`gotgenes/pi-packages`** — `packages/pi-subagents-worktrees`: registers a `WorkspaceProvider` with the pi-subagents core (opt-in per agent type via `subagents-worktrees.json`). Rescue semantics are the distinctive part: if the child ends with a question, the worktree is kept for resume; on completion with changes, work is committed to `pi-agent-<id>` (retry once with `--no-verify` if a hook rejects, re-staging hook-rewritten files, and noting "Commit hooks were bypassed to save this work"); uncertain cleanup **leaves the worktree in place** with a note and names rescue branches/worktrees in a startup warning. "This package never deletes [a rescue branch] for you." https://github.com/gotgenes/pi-packages/tree/main/packages/pi-subagents-worktrees
- **`pi-oilrig/oilrig-trunk`** — `/trunk` experiment routine driven by the external `worktrunk.sh` (open/verify/keep/drop, with a ledger so refuted ideas are not retried), a `trunk_dispatch` tool that creates a worktree with write-scope pre-configured and returns "a `pi -p` command to run the agent there", a `trunk_cleanup` tool limited to `.pi/worktrees`, and a `write-scope` guard whose key design decision is that a scope *file* alone is not enough: "A worktree keeps its `.pi/write-scope` forever, so the old rule meant every later session in that checkout inherited a finished worker's containment" — enforcement now requires a pipeline role signal (`globalThis.__gantt.role`), `$CREW_HANDLE`, or deliberate `$PI_WRITE_SCOPE`. `/scope unlock|lock|auto|set|add|clear|reload|status` is the escape valve; OS-level confinement is delegated to `pi-sandbox.sh` (bubblewrap). Also documents a dead integration: `worktree-setup.sh` was "previously wired as a `pi-subagents` `worktreeSetupHook`, but that host is no longer installed". https://github.com/pi-oilrig/oilrig-trunk
- **`ant1b0t/Pi`** — `extensions/worktree/worktree-tool.ts`: a single `worktree` tool that creates a detached worktree in `mkdtemp`, runs one shell command inside it (SIGTERM→SIGKILL timeout, abort-aware, output truncated head/tail), returns stdout/stderr/exit code, then removes the worktree. Pure "throwaway command isolation" — no session, no branch persistence. https://github.com/ant1b0t/Pi/tree/main/extensions/worktree

### 3.3 Effective-cwd routing without moving the session

These treat the worktree as an execution target, not a session home.

- **`bry-guy/pi-ez-worktree`** — the canonical statement of this pattern, with an explicit **composition contract** in its README: it overrides `bash`, `read`, `write`, `edit`, `grep`, `find`, `ls`, and `user_bash` to route into the active worktree (relative project paths redirected; absolute paths outside the repo left alone). "This is an **effective cwd** / tool-routing layer, not a full process cwd change": it does *not* move the Pi process, does *not* rewrite the session header cwd, does *not* retarget pickers/autocomplete. For integrators: "Treat `pi-ez-worktree` as a routing primitive, not a session-relocation primitive... Do not assume a child session should be started with its cwd set directly to the worktree path" — cleanup and `git worktree remove` are less likely to fight a still-live session rooted inside the worktree; starting a child directly in the worktree is "opt-in behavior with tradeoffs". Metadata (`.pi-ez-worktree.json`) is written inside each worktree and added to the worktree's local exclude so re-attach can recover base branch and main checkout. Finish flow: auto-commit → rebase in the worktree → ff-merge from the original checkout → remove; rebase conflicts are left in the worktree so the live session can resolve them with full context. A plan doc (`docs/plans/gondolin-native-worktrees.md`) records a real integration failure with pi-chat/Gondolin sandbox delegation and proposes lazy registration so inactive sessions don't steal delegated `/workspace` tools. https://github.com/bry-guy/pi-ez-worktree
- **`jordyvanvorselen/pi-bare-worktrees`** — for `--bare` checkouts (`.bare/` + `main/` + `feat/login/`); turns itself off outside that layout. Routing via `tool_call` rewriting: bash gets `cd <worktree>` prepended, relative `path` args are re-rooted, cwd-defaulting tools get the worktree as `path`, and subagent tools get `input.cwd = active.path` when unset. Enforcement table (README): protected branches block `edit/write` and mutating bash (regex-classified), and — notably — block *all* `git worktree`/`git switch`/`git checkout <branch>` including in feature worktrees, so the path-equals-branch invariant holds. Optional session move is explicit and separate: `/wt sync` forks + switches the session into the active worktree (`src/commands.ts` `switchSessionTo`), and the UI hints "Tools run in X. Run /wt sync to move the session there." Shared env files are symlinked from `<root>/.shared-env/`; state survives `/resume` via session custom entries. https://github.com/jordyvanvorselen/pi-bare-worktrees
- **`aryan-binazir/pi-extensions`** — `extensions/worktree/index.ts`: same routing family, implemented with the newer APIs: `createBashToolDefinition(cwd, { spawnHook: ctx => ({...ctx, cwd}) })` for bash, `user_bash` operations replacement, path rewriting for `read/write/edit/grep/find/ls`, a system-prompt notice ("session storage, loaded context/resources, and arbitrary extension internals are not relocated"), footer status, and a custom session entry (last matching entry wins, scanned back-to-front) so the active worktree survives `/resume` and session-tree navigation. https://github.com/aryan-binazir/pi-extensions/tree/main/extensions/worktree
- **`blarghmatey/dotfiles`** — `home/.pi/agent/extensions/virtual-cwd.ts`: `/cd [worktree <name>]` implements a *virtual cwd* with the same interception set (bash gets `cd <vCwd> && ...` prefixed; `user_bash` is re-hosted via `createLocalBashOperations().exec(command, vCwd, ...)`; relative paths resolved; grep/find `paths[]` handled); footer shows `⌂ <dir>` when the virtual cwd differs from launch. https://github.com/blarghmatey/dotfiles
- **`kesor/pi-worktree`** — `/worktree create|list|remove|reset|cd|prune|status` plus matching tools; worktrees in `.pi/worktrees/`, branches prefixed `feature/`, lock files to prevent concurrent create/remove, and auto-adding `.pi/worktrees/` to the *global* gitignore. https://github.com/kesor/pi-worktree
- **`thisuxhq/pi-worktree`** (`@thisux/pi-worktree`, npm) — `/worktree ls|add|open|rm|pr <n>`: sibling-folder layout (`~/AGI/mobile-fix-login/`), `pr` fetches via `gh` and creates the worktree; create/open output ends with `Next: cd <path> && pi` and copies the path to the clipboard (pbcopy) — i.e. it deliberately does *not* switch the session. https://github.com/thisuxhq/pi-worktree
- **`FradSer/pi-packages`** — `worktree.ts` (path-redirect hook, see §2.7) and `worktree-completion.ts` (autocomplete scoping, see §2.7).
- **`Stupremee/pi`** — `extensions/worktrunk/`: thin Pi wrapper around the external [Worktrunk](https://worktrunk.dev) CLI (`/wt` and `/worktree` for create/list/status/remove/commit/squash/rebase/push/merge/prune, plus session-state markers 🤖💬❓✅). README states the constraint that defines this whole family: "Directory-changing commands use `--no-cd`: an extension subprocess cannot change Pi's working directory. `/wt cd <name>` prints the matching path so it can be used in a new terminal/session." https://github.com/Stupremee/pi/tree/main/extensions/worktrunk
- **`JarenKempton/pi-config`** — `extensions/generic-worktrees.ts`: `worktree_create` tool + `/worktrees` picker with copy/delete/create; config-driven branch/path templates from a `.pi/worktrees.json`, ticket integration (Jira via `acli`/`jira` CLIs) for branch naming; no session switching at all. https://github.com/JarenKempton/pi-config
- **`jordyvanvorselen/pi-bare-worktrees`** is also notable for what it *doesn't* run: "No git process on session start or on tool calls. Root detection, worktree listing and link checks read the filesystem."

## 5. Failed or intentionally unsupported approaches

1. **`process.chdir()` mid-session.** Structurally broken: `AgentSession._cwd` is frozen at construction and tools capture cwd in closures (#2619, #2992; badlogic: "currently unsupported"). `ZENTUI_FINAL_CWD` shell-side capture exists but has no consumer (#5478). PR #2101 (setCwd API) was closed. One shipping artifact remains: the runtime itself chdirs on *session replacement*, so `process.cwd()` tracks the active session only across switches (noted in Cygnusfear's `/cwd` completions comment).
2. **Terminal-injection relaunch (`cmux send` / `tmux send-keys` + `sleep 0.3`).** Documented as failed by its own users: PR #2101's description says it "only works in cmux/tmux environments (bare terminal users are out of luck)", "is inherently racy (relies on a `sleep 0.3` delay)", and "causes a visible session restart" (https://github.com/earendil-works/pi/pull/2101). It is still the only option in `xiaoyu2er/pi-worktree` and `EugeneKallis/pi-feature` (`relaunchInPlace`), both of which keep a `sleep 0.3` and a detached spawn so the keystrokes outlive Pi's shutdown; EugeneKallis adds a Herdr arm (`herdr pane run <paneId> "cd '<wt>' && pi"`, no trailing newline needed since `pane run` submits atomically). Treat these as legacy-shaped.
3. **Changing a live process's cwd via multiplexer pane moves.** Herdr explicitly cannot: "pane move... a moved running process retains its launch-time Herdr IDs and the old pane ID remains an alias. It offers no command to change a running process's cwd. Moving the Pi pane is layout-only, not a worktree-shell restart" (giuseppecrj/pi-herdr-agents research doc). The same document's verdict applies ecosystem-wide: a truthful "same process, new worktree" handoff requires an external supervised restart protocol (persist fork + launch intent → exit Pi → external launcher runs `cd <wt> && pi --session <fork>`), and no public API provides it as one atomic operation.
4. **`ctx.switchSession()` from tool handlers or `agent_settled`.** Not exposed: `switchSession` lives on `ExtensionCommandContext` only. Tool handlers must instead use the gabrielmbmb pattern (tool queues, `terminate: true`, `agent_settled` re-dispatches a `/worktree --continue` command) or the Vessup pattern (prototype patch + hold-the-run-open). The `runWhenIdle`/`requestSessionSwitch` proposals that would make this safe were closed (#8554, #9632).
5. **Worktrunk/provider availability assumptions.** `nicobailon/pi-subagents` treats `worktreeProvider: "worktrunk"` as a hard error when the `wt` CLI is unavailable or combined with a custom base dir, and auto-selects native git otherwise (source: `resolveWorktreeProvider`). `pi-oilrig/oilrig-trunk` documents that its `worktreeSetupHook` wiring was removed because its former host (`pi-subagents`) "is no longer installed" — cross-extension hook contracts are not a stable integration surface.
6. **In-repo worktree directories for extension repos.** `nicobailon/pi-subagents` (lane doctrine) and `ogulcancelik/pi-subagents`-adjacent guidance converge on: keep lane worktrees *outside* auto-discovered extension directories like `~/.pi/agent/extensions`, or a stale extension worktree auto-loads duplicate tools/shortcuts. Pi's own `#2558` documents the collision class (sibling worktrees' project-local `.pi/extensions` registering duplicate commands in one runtime).
7. **Extension worktrees inside the repo.** Several extensions place managed worktrees at `<repo>/.pi/worktrees/` (kesor, yan-xie-nk, BrandonMathis, FradSer redirect, pi-oilrig, ant1b0t uses `/tmp`); others deliberately place them *outside* (`~/.worktrees/` — narumiruna; `~/.pi/worktrees/<host>/<repo>/` — dingdinglz; sibling folders — thisuxhq; `../worktrees/<repo>/` — steflsd). There is no consensus; the in-repo choice requires the exclude-file dance (BrandonMathis `.git/info/exclude`, kesor global gitignore) and interacts with Pi's context-file walking (#6617/#7221 — fixed only for *nested* worktrees, not for in-repo `.pi/worktrees/<branch>/` trees, which stay inside the ancestor walk).

## 6. Gaps and open questions

- **No official example, no official flag.** Pi ships neither a `--worktree` flag nor a worktree example; the maintainers' stated direction was "the new extension api" (#4423) but the shipped API gained `switchSession`/`newSession`/`fork` without cross-cwd parameters, so ecosystem extensions converged on `SessionManager.forkFrom` + header surgery. A future core `ctx.relocateSession`/`fork({ cwd })` (#9162/#8269) would obsolete a large fraction of the duplicated plumbing above (eager header writes, parent-pointer cleanup, stale-ctx handling).
- **Session discovery across worktrees is unsolved.** Per-cwd session buckets mean `/resume` in a worktree doesn't see the main checkout's sessions and vice versa; #8271 (common-dir grouping) and Dispatch's cross-checkout `resume` picker and #9754 (same-repo project identity) are the only public attempts.
- **Absolute-path contamination after a fork is documented but barely solved.** Only alennartz injects a `worktree:moved` correction message. Forks copy raw absolute paths from the old checkout; everything else relies on the model not to reuse them.
- **No worktree feature is covered by upstream tests.** Everything here lives in third-party repos; the only upstream worktree tests are footer/resource-loader unit tests (`footer-data-provider.test.ts`, `resource-loader.test.ts`).
- **Interaction between routing-layer extensions and session-relocation extensions is unspecified.** pi-ez-worktree's composition contract is the only written guidance; two routing extensions in one session, or a router plus a switcher, will fight over `tool_call` rewriting order.

## 7. Relevance to this repository

This repo's agent stack (`herdr-bridge`, `herdr-subagent`) builds on Herdr panes, and Herdr's CLI already owns worktree create/open/remove with parent-grouped workspaces (`herdr worktree ...`) plus pane moves. The survey suggests the natural fit for a pi-monorepo worktree feature is the **giuseppecrj handoff model** (fork session → `herdr worktree create --no-focus` → `herdr pane run <root-pane> 'cd <wt> && pi --session <fork>'` → focus), with pi-ez-worktree's composition contract as the guardrail against claiming "in-place relocation", and alennartz's two fixes (eager header write; `worktree:moved` absolute-path warning) applied to any session fork. Nothing above requires modifying Pi itself.
